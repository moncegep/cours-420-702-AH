## Section 2 — Mise en situation web

### Contexte

Tu es développeur dans une équipe web. Le serveur de développement contient l'arborescence suivante pour ton projet:

```
/github/projet-web/
├── public/
│   ├── index.html
│   ├── apropos.html
│   ├── style.css
│   └── images/
│       ├── logo.png
│       └── banniere.jpg
├── config/
│   └── nginx.conf
└── logs/
    └── access.log
```

**Contexte utilisateur:**

- Ton compte: `dev`, groupe primaire `dev`, groupe secondaire `web-team`
- Le serveur Nginx tourne sous l'utilisateur `www-data`, qui est aussi membre de `web-team`
- Tu n'as **pas** sudo, sauf indication contraire

---

### Tâche 1 — Navigation

Tu te trouves dans `/home/dev`.

**1.a)** Écris la commande pour aller dans le dossier `images/` du projet en utilisant un **chemin absolu**.

**1.b)** Tu te trouves maintenant dans `/github/projet-web/public/images`. Écris la commande pour te rendre dans `/github/projet-web/config/` en utilisant un **chemin relatif**.

---

### Tâche 2 — Création de dossiers et de fichiers

**2.a)** Tu veux créer un nouveau dossier `videos` à l'intérieur de `public/`. Tu te trouves dans `/home/dev`. Écris la commande, en utilisant un chemin absolu.

**2.b)** Tu veux maintenant créer un fichier vide `intro.txt` dans le dossier `videos/`. Lesquelles des commandes suivantes accomplissent correctement cette tâche? Indique pour chacune si elle fonctionne et, sinon, pourquoi.

### Tâche 3 — Renommer et déplacer

**3.a)** Tu veux **renommer** le fichier `apropos.html` en `a-propos.html` (sans le déplacer). Tu te trouves dans `/srv/projet-web/public/`. Lesquelles des commandes suivantes fonctionnent?

### Contexte: Studio Trame
 
**Studio Trame** est une PME québécoise spécialisée en développement web. L'effectif:
 
| Personne | Rôle |
|---|---|
| Marie, Olivier | Développeurs frontend |
| Pascale, Quentin | Développeurs backend |
| Renée, Samuel | Designers/intégrateurs |
| Théo | Chef de projet (suit l'avancement, ne code pas) |
| Ulysse | Administrateur système |
| Vivienne | Stagiaire affectée à `projet-alpha` |
| William | Stagiaire affecté à `projet-beta` |
 
L'entreprise opère un serveur Linux unique qui héberge:
 
- **Deux projets clients en cours**: `projet-alpha`, `projet-beta`
- **Le site web public de Studio Trame** (servi par Nginx, utilisateur de service `www-data`)
**Contraintes imposées par les contrats avec les clients (NDA):**
 
- Le code et les données de chaque projet client sont **strictement confidentiels**: les développeurs assignés à un projet ne doivent pas pouvoir lire l'autre projet.
- Les **designers** travaillent sur les deux projets (besoin d'écriture sur les assets).
- Chaque **développeur** est assigné à un seul projet.
- Les **stagiaires** n'accèdent qu'au seul projet auquel ils sont assignés.
- Le **chef de projet** (Théo) doit pouvoir **lire** les deux projets pour faire le suivi, mais n'a pas besoin d'écrire.
- Seul **Ulysse** détient `sudo`.
**Affectations aux projets clients:**
 
| Projet | Frontend | Backend | Designers | Stagiaire |
|---|---|---|---|---|
| alpha | Marie | Pascale | Renée, Samuel | Vivienne |
| beta | Olivier | Quentin | Renée, Samuel | William |
